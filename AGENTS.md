- Store Books Store slider images in three fixed, admin-managed `books_store_banners` slots, reusing protected admin image uploads; this enforces the three-slide limit while keeping public reads separate from marketplace banners.
- Persist each Msosi checkout's delivery batch and hostel zone on `food_orders`; this keeps kitchen summaries queryable and vendor-scoped by existing order RLS.
- Hostel batch pre-orders live in standalone `preorder_meals` (admin-managed) and `batch_preorders` (public insert, admin read) tables with no payment; regular `food_orders` checkout stays free of batch/hostel fields so the two flows never mix.
- Render the shared hostel pre-order experience at both `/preorder` and `/msosi/preorder`; this preserves direct links while keeping one form implementation.
- Serve HTML documents with no-store headers while leaving hashed assets cacheable; this prevents old page shells from flashing after releases.
- The app-shell service worker is generated by vite-plugin-pwa as /sw.js and registered only from src/lib/pwa.ts, which refuses dev/preview/iframe contexts; this keeps offline caching from ever serving stale previews.
- Admin order push uses Firebase Messaging with a separate /firebase-push/ worker scope, admin-owned device records and per-event/device send logs; this preserves app-shell caching and prevents duplicate alerts or notifications to demoted admins.

- Capture the native install event in the root document head and consume it only from the install button click; this prevents hydration timing from losing Chrome prompts without showing automatic popups.
- Use the shared browser image compressor for listing creation/edits and admin food/pre-order photo uploads; one implementation enforces WebP output and upload size limits without changing other admin artwork.
- Create per-router QueryClients through the shared query policy: public catalogs cache for five minutes, operational reads for one minute, with no timer/focus/reconnect polling; mutations invalidate the relevant keys so edits still appear immediately.
- Share user-keyed access/profile/voucher queries and reset caches on identity changes, not token refresh; this prevents account-dependent contacts, roles and orders from surviving account switches.
- Vendor order feeds use unique, vendor-scoped INSERT/UPDATE subscriptions with burst-debounced exact-key invalidation and reconnect recovery; always remove channels and pending timers on unmount or vendor change.
- Product detail uses a query under the products invalidation prefix; this keeps cached detail data synchronized with listing edits and moderation.
- Public listing feeds use filter-keyed infinite queries with 16-row active summary pages and deterministic ordering; category/search filtering happens before pagination so later matches remain discoverable.
- Cache successful login-streak touches by user and UTC date, matching the server calendar; never stamp failures or share an account's daily guard with another account.
- Listing image uploads use new object paths, no overwrite, and year-long cache headers; changed photos get new URLs instead of stale cached bytes.
